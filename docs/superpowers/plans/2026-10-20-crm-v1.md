# CRM v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the owner and staff a trilingual admin at `/[locale]/admin` to manage cars, photos, customers, rental bookings, sales and payments in Supabase, and switch the public showroom to read published stock from it.

**Architecture:** Postgres (Supabase) holds all rules that matter — no double-booking (exclusion constraint), owner-only fields (trigger), permissions (RLS), public projection (`public_cars()` / `public_car()` security-definer functions). The Next.js app reads/writes as the signed-in user through `@supabase/ssr` in Server Components and Server Actions; the public showroom reads through a cookie-less client inside `src/lib/listings.ts`, cached under the tag `listings` and revalidated by admin saves. Pure logic (mapping, money, slug, error mapping, form schemas) lives in `src/lib/crm/` and is unit-tested with Vitest; database rules are tested with pgTAP.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript strict, Tailwind v4, Supabase (Postgres 15+, Auth, Storage), `@supabase/supabase-js`, `@supabase/ssr`, `zod`, Supabase CLI (`supabase` npm dev-dep, Docker for the local stack), Vitest, pgTAP.

**Spec:** `docs/superpowers/specs/2026-10-20-crm-design.md` — read it alongside this plan; section numbers below (§n) refer to it.

## Review Focus

1. **The last active owner demotes or deactivates themselves** → must be refused ("There must be at least one active owner"), otherwise the shop is locked out of its own admin. Test in Task 2.
2. **Staff edits an existing booking's dates so it now overlaps another** (update, not insert) → refused with the clash message, same as on create. Test in Task 1.
3. **"Today" near midnight on Vercel (UTC)** → pickups/returns/overdue must use the Tunis date (UTC+1, no DST): at 23:30 UTC on 14 March it is already 15 March in Sousse. Test in Task 8.
4. **Amounts typed on an Arabic or French keyboard** (`٤٥٠`, `1 250,5`, `1.250,500`) → parsed to 450 / 1250.5 / 1250.5, not rejected or misread. Test in Task 8.
5. **Car names with accents or only Arabic letters** (`Citroën C3`, `سيارة`) → a valid slug (`citroen-c3-2021`, `car-2021-xxxx`), never an empty or invalid slug that fails the DB check. Test in Task 8.
